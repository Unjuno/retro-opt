## Solver validation

### Random acyclic stochastic graph

`experiments/solver_random_dag_crosscheck/` で6-state stochastic DAGを200ケース生成し、value iterationと全deterministic stationary policy総当たりを照合した。

- cases: 200
- mismatches: 0
- max absolute error: 0.0 s

### Retry / self-loop SSP

`experiments/solver_retry_crosscheck/` でself-loopを持つretry問題を200ケース生成し、解析解とvalue iterationを照合した。

- cases: 200
- mismatches: 0
- max absolute error: 約 `9.54e-12 s`

これらはsmall-state validationであり、一般の大規模cyclic SSP全体の完全な証明ではない。

## Observation constraint

hidden RNGが違っても人間から同じObservationに見えるstate群では同一actionを強制する、小規模用の全policy総当たりreference solverを追加した。

これにより、内部RAM/RNGをmodel解析へ利用しつつ、Competition policyへclairvoyant informationを漏らさない境界を明示できる。

## DQ6 sensitivity experiments

### 1. `dq6_early_break_even`

追加戦闘1回がEXP閾値を跨ぐことで、後続から何秒削れば期待値上得になるかを計算。

### 2. `dq6_early_policy`

現在EXPによってfight/skip境界が変わることを確認。固定ruleではなくstate-dependent policyになる。

### 3. `dq6_early_horizon`

同じEXPでも、ボスまでに残るencounter opportunity数によってactionが変わり得ることを確認。

### 4. `dq6_metal_kill_sensitivity`

Metal Slimeのappearanceとkill successを分離。アモール北B2の約20%という公開参考値はappearanceであり、EXP獲得確率ではないため、撃破率を別パラメータとして扱う。

## Route objective experiment

`experiments/repeated_attempt_objective/` で、成功run単体の速さと「目標successを1回得るまでの期待壁時計時間」が一致しないことを確認した。

IID attemptの単純モデルでは、success probabilityを `p`、成功時平均を `Ts`、失敗時平均を `Tf` とすると、期待壁時計時間は

```text
Ts + ((1 - p) / p) * Tf
```

となる。将来のChart Atlasでは平均タイム・完走率・target突破率等と並べて保持する。

## 現時点で判明した設計上の要点

1. `EXP >= Xなら狩る`のような単一閾値だけでは不十分。
2. policyは少なくとも `(EXP, 残り経路, 残りencounter機会, downstream value)` に依存し得る。
3. Metalのappearance rateとreward probabilityを混同しない。
4. hidden RNGを解析へ使っても、Competition policyではObservation単位でactionを拘束する。
5. 最速成功runと、目標successまでの期待壁時計時間最小routeは一致しない場合がある。
6. 実測前は最適タイムを主張せず、decision boundaryとmeasurement priorityを出す。
